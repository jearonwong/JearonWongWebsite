# AIIRWP Post-Release Monitoring SOP

## Scope

This SOP describes how to monitor AIIRWP after the owner manually executes a release announcement. It does not execute release actions and does not claim any external evidence before observation.

## First 7 Days

Daily checks after owner release execution:

1. Verify the AIIRWP route, HTML, PDF, manifest, and checksums are still reachable.
2. Check LinkedIn Newsletter/post engagement if the owner published.
3. Check X post/thread engagement if the owner published.
4. Run the approved Google and Bing query set.
5. Run the approved AI answer-engine query set where practical.
6. Check for backlinks, citations, and reposts.
7. Record only observed URLs, timestamps, screenshots, and notes.

## First 4 Weeks

Weekly checks:

1. Repeat search engine query checks.
2. Repeat answer-engine query checks.
3. Review backlinks and citation mentions.
4. Review public comments and expert replies.
5. Review inbound messages that the owner authorizes for logging.
6. Check whether any clarification, correction, or boundary note is needed.

## First 3 Months

Monthly checks:

1. Re-run core search and answer-engine queries.
2. Review authority signal tracker for evidence quality.
3. Separate visibility evidence from adoption or endorsement claims.
4. Decide whether new public pages, FAQs, or corrections are justified.
5. Decide whether a separately authorized Final Seal wave should be considered.

## Search Engine Checks

Use the query list in `monitoring-tracker.md`. Record:

- query
- engine
- date
- result found
- position or short summary
- cited URL
- screenshot path
- next action

## AI Answer Engine Checks

For Perplexity, ChatGPT, Claude, Gemini, Grok, and Genspark, record:

- exact prompt
- date/time
- answer summary
- whether AIIRWP is cited or mentioned
- cited URL if provided
- screenshot/export path
- limitation notes

Do not claim answer-engine recognition unless an observed answer is recorded.

## Backlink and Engagement Checks

For backlinks, shares, comments, reposts, newsletter metrics, expert replies, and inbound messages:

- record the exact public URL where available
- record screenshot path
- distinguish private feedback from public evidence
- do not infer endorsement, adoption, certification, or insurer acceptance

## Evidence Capture Rules

- Use `evidence-capture-log.md` for every captured item.
- Use stable IDs: `AIIRWP-R8-EVID-###`.
- Record timestamps with timezone when available.
- Store screenshots under a future owner-approved evidence folder.
- Never fabricate evidence fields.
- Leave unknown fields blank.

## Screenshot Naming Convention

Recommended format:

`aiirwp-r8-YYYYMMDD-platform-query-or-channel-short-description.png`

Examples:

- `aiirwp-r8-20260521-linkedin-newsletter-post.png`
- `aiirwp-r8-20260522-google-agentic-ai-insurability.png`
- `aiirwp-r8-20260523-perplexity-aio-query.png`

## Website Update Rules

Consider a website update only when:

- a factual correction is required
- a link breaks
- a boundary statement needs clarification
- new evidence deserves an evidence-registry update
- owner approves a post-release evidence update

Do not update public surfaces to claim adoption, certification, endorsement, coverage-ready status, underwriting-ready status, legal proof, insurance advice, or SEO/GEO outcome.

## Correction Patch Rules

Create a correction patch when:

- a public link breaks
- metadata becomes stale
- a typo changes meaning
- a boundary statement is unclear
- a citation/artifact URL fails

Correction patches must preserve artifact integrity unless an artifact defect is verified.

## Final Seal Consideration

Final Seal may be considered only after separate owner authorization. Release execution, comments, shares, backlinks, indexing, or answer-engine mentions do not automatically authorize Final Seal.
