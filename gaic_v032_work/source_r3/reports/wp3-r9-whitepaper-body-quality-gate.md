# WP3-R9 Whitepaper Body Quality Gate

## Purpose

This gate must pass before any future AIIRWP publication candidate, public HTML artifact, or public PDF artifact is generated.

## Gate Questions

1. Does the document read like a white paper, not a source pack?
2. Can an intelligent non-specialist understand Chapter 0-3 without prior context?
3. Does the first third define the industry problem before introducing object models?
4. Does every chapter have a clear argument, not just a mapping table?
5. Are source notes hidden into proper citation format?
6. Are internal QA/source/package artifacts excluded from the body?
7. Does it match GAIC/AIAAWP writing tone and visual system?
8. Would an insurer or risk executive read this as a serious industry paper?
9. Would a CTO, CRO, or CFO understand why lifecycle evidence matters?
10. Does it avoid overclaim while still being concept-defining?

## Hard Fail Conditions

- Raw source markers visible in the body.
- Internal QA reports visible in the body.
- Source inventory rendered as main content.
- AIO/AIRM introduced before reader pain is established.
- Document mostly tables, mappings, or checklists.
- Visual style diverges from GAIC/AIAAWP.
- Public artifact generated before this body gate passes.
- Internal pipeline or package status language appears in reader-facing body.
- Evidence replaces argument rather than supporting it.
- Insurance/legal boundary is either missing or over-expanded into procedural noise.

## Required Evidence for Pass

- Chapter 0-3 reader-path review.
- Body ratio check.
- Source marker conversion check.
- Internal artifact exclusion check.
- GAIC/AIAAWP tone comparison.
- Executive-reader skim review.
- Boundary/claims review.
- Visual system review before artifact generation.
