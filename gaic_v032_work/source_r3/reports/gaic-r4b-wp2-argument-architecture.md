**Status:** Architecture baseline

## Core Thesis

AI agent auditability requires a new audit object: lifecycle-responsibility-linked agent work.

## Core Definition

Agentic AI Auditability is the ability to reconstruct, test, and evidence agentic lifecycle work across authority, responsibility, tools, outcomes, exceptions, and remediation.

## Fixed Core Line

AI agent auditability cannot be built on logs alone.

An agentic system becomes auditable only when its lifecycle work can be reconstructed through responsibility-linked evidence chains.

## Public Explanation Levels

### One Sentence

AI agent auditability means reconstructing responsibility-linked lifecycle work, not merely collecting logs.

### One Paragraph

WP2 should argue that agentic systems become auditable only when lifecycle work can be reconstructed across authority, human and agent responsibility, tool actions, accepted outcomes, exceptions, privacy boundaries, and remediation closure. Logs and traces are useful ingredients, but they are not audit evidence chains unless they are linked to lifecycle responsibility objects.

### Three-Minute Explanation

Traditional AI audit often starts with the model: documentation, evaluations, controls, outputs, monitoring, and risk management. Agentic AI changes the audit object. The thing to audit is no longer only a model output. It is lifecycle work: who authorized the agent, what tools it used, which human role was responsible, which outcome was accepted, what exception occurred, what evidence survived, and how remediation closed.

That is why logs alone are not enough. Logs can show that an action happened. They may not show whether the action was authorized, whether the right human role was responsible, whether the evidence can be selectively disclosed, whether the customer outcome was accepted, or whether a dispute was remediated.

WP2 turns WP1's lifecycle responsibility objects into audit evidence objects. It should define the object chain from Compliance Object to Audit Evidence Object to Insurable Risk Object. WP2 owns the middle layer: the evidence that makes lifecycle work reconstructable and testable by audit, assurance, internal governance, and qualified review stakeholders.

### Expert Explanation

WP2 should formalize an agentic audit object model. The core unit of analysis is lifecycle-responsibility-linked agent work, not isolated model output or generic execution trace. The paper should translate MROs into audit evidence objects that bind role, authority, tool action, evidence pointer, privacy boundary, accepted outcome, exception state, and remediation closure.

This creates a bridge from WP1's Compliance Object layer to downstream assurance and insurability analysis. The paper should define readiness conditions, evidence request lists, evidence partitioning, privacy-preserving disclosure, third-party validation boundaries, and AARM levels. It must remain non-audit-standard and non-certifying: it supports auditability readiness and evidence architecture, not audit opinions or regulatory approval.

## Objection Handling

| Objection | Answer direction | Boundary to avoid |
|---|---|---|
| Is this just more logging? | No. Logs are activity records. Audit evidence chains bind logs to role, authority, tool action, accepted outcome, exception, privacy boundary, and closure. | Do not imply logs are useless. |
| Is this biased toward MPLP? | WP2 can mention protocol paths only as examples. The architecture is MRO/evidence-chain based and must be usable without MPLP. | Do not imply MPLP is required or industry-standard. |
| Is this an audit standard? | No. It is an authored industry definition and readiness framework for agentic auditability. | Do not claim audit standard, assurance standard, or regulator approval. |
| Can Big Four already do this? | Audit and assurance firms can adapt existing technology risk methods, but agentic lifecycle work creates object requirements that ordinary model/output audit may not capture. | Do not claim Big Four endorsement or deficiency. |
| How is this different from model governance? | Model governance audits model behavior and controls. WP2 audits lifecycle work across authority, responsibility, tools, outcomes, exceptions, and remediation. | Do not say model governance is unnecessary. |
| How is this different from ordinary IT audit? | IT audit reviews systems, controls, access, change, and operations. WP2 adds agentic lifecycle responsibility objects and evidence chains for delegated autonomous work. | Do not replace IT audit or professional judgment. |
| Is HITL enough? | HITL is evidence only when linked to role, delegated authority, evidence, accepted outcome, and escalation/closure state. | Do not dismiss human oversight. |
| Is Validation Lab certification? | No. Validation Lab remains a non-certifying evidence adjudication example. | Do not claim certification, audit opinion, or conformity assessment. |
| Can enterprises use this without MPLP? | Yes. WP2 defines audit evidence architecture independent of any single protocol path. | Do not make WP2 an MPLP-only guide. |
