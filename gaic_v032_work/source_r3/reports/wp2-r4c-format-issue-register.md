# WP2-R4C Format Issue Register

**Status:** FORMAT REPAIR DEFERRED

## Registered Issues

- PDF formatting is not accepted for publication.
- DOCX formatting is not accepted for publication.
- HTML is usable for content review but still requires a dedicated publication design pass before public use.
- R4C intentionally does not fix formatting.
- Candidate artifacts generated in R4C are content/naming QA artifacts only.

## Required Future Recommendation

The next format/publication design wave should use a proper publication layout process:

- Choose DOCX-first or HTML-publication-template-first workflow.
- Define document styles, title page, TOC, page breaks, table styles, headers/footers, citation layout, and artifact metadata rules.
- Render and visually inspect every DOCX page before PDF export if DOCX-first.
- Generate PDF only after DOCX/HTML layout passes visual QA.
- Check HTML responsive version separately for mobile readability.
- Treat wide tables and source/citation sections as high-risk layout objects.

## R4C Boundary

No formatting pass was attempted. Naming/content synchronization required regeneration, but visual/layout acceptance remains explicitly open.
