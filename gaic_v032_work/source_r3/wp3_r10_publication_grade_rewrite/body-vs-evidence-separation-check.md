# WP3-R10 Body vs Evidence Separation Check

## Separation Review

| Check | Result | Notes |
| --- | --- | --- |
| Body presents the industry problem first | PASS | Chapters 0-3 open with reader pain, not method. |
| Body avoids raw source inventory | PASS | Detailed source IDs stay in the source notes appendix and external reports. |
| Body avoids raw source marker tags | PASS | The body uses numbered notes instead of `[SRC: ...]` / `[INT: ...]` tags. |
| Body avoids internal QA / pipeline language | PASS | QA and validation language are kept out of the reader-facing prose. |
| Body keeps evidence subordinate to argument | PASS | The evidence appears as support, not as the main content. |
| Evidence package remains explicit | PASS | Appendices and supporting files carry the object references and source notes. |
| AIO / AIRM stay analytical, not procedural | PASS | They are introduced as authored vocabularies, not as process steps. |
| No public artifact language appears in the body | PASS | The body does not promise publication, release, or finality. |

## Separation Rule Summary

The body is for the reader. The evidence package is for traceability. The body should persuade, explain, and define. The evidence package should support and verify. R10 keeps those roles separate.
