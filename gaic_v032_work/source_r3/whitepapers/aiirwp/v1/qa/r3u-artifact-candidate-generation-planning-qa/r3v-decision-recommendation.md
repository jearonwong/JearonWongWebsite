# R3V Decision Recommendation

## Recommended Next Wave

`R3V-CANDIDATE-SOURCE-PREPARATION-PLANNING`

## Why

R3U finds that R3T stayed generation-planning-only and produced a stable candidate generation planning package. R3T correctly separates the R3P internal integrated draft from a future controlled publication-candidate Markdown source and keeps HTML/PDF/manifest/checksum generation blocked.

Candidate source preparation planning is the correct next step because the next risk is not artifact generation; it is defining how a future candidate source would be prepared, named, preserved, scanned, and gated without mutating the R3P integrated draft or changing public status.

## Specific Next Tasks

- Plan the candidate source preparation workflow without creating the source.
- Define source input, candidate source path placeholder, naming convention, and status language.
- Define preservation scans for Chapters 1-28, Appendix A-H, Appendix I deferred note, source refs `[1]` through `[62]`, and table IDs.
- Define non-claim and public-status checks for the candidate source.
- Define stop gates before candidate source creation, artifact generation, public route restoration, public CTA restoration, public staging, public candidate status, final/sealed status, release-ready status, or public release.
- Decide whether source gaps remain strengthening opportunities or require a later source-strengthening wave before creation.

- Artifact generation.
- Publication-candidate Markdown creation.
- HTML/PDF/DOCX creation.
- Manifest/checksum creation.
- Public route restoration.
- Public CTA restoration.
- Public staging.
- Public candidate, final, sealed, release-ready, or public release status.
- Source-strengthening research unless separately authorized.
