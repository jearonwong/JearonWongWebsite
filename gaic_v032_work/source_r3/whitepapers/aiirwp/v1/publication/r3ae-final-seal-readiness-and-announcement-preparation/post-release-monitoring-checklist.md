# Post-Release Monitoring Checklist

**Status:** Prepared only. Not executed in R3AE.

## Link And Artifact Monitoring

- [ ] Monitor public route availability.
- [ ] Monitor public HTML artifact availability.
- [ ] Monitor PDF download success.
- [ ] Monitor manifest and checksum availability.
- [ ] Re-run checksum validation after deployment and after announcement traffic begins.

## Conversation And Claim-Risk Monitoring

- [ ] Monitor LinkedIn comments if announcement is later posted.
- [ ] Monitor X replies and repost framing if announcement is later posted.
- [ ] Triage misreadings that convert evidence into coverage, auditability into insurability, or governance into claim approval.
- [ ] Preserve boundary language in responses.
- [ ] Do not answer insurer/regulator questions as legal, insurance, coverage, underwriting, claim, pricing, or compliance advice.

## Correction Policy

- [ ] Record factual correction requests.
- [ ] Separate typo/link corrections from source-content corrections.
- [ ] If artifact correction is required, create a new governed repair wave.
- [ ] Refresh manifest/checksum after any artifact byte change.
- [ ] Preserve prior version traceability.

## External Inquiry Boundary

- [ ] For insurer or broker inquiries, state that the paper is research and does not provide coverage advice, underwriting guidance, premium recommendation, claim approval guidance, proof of insurability, or insurer-adopted method.
- [ ] For regulator or legal inquiries, state that the paper is research and not legal advice, legal liability determination, regulator approval, or compliance proof.

## Rollback Path

- [ ] If a public issue is found, remove or de-emphasize artifact CTAs while preserving internal evidence.
- [ ] Restore a bounded hold notice if required.
- [ ] Keep rejected v0.2 excluded as source truth.
- [ ] Document rollback in governance and reports.
