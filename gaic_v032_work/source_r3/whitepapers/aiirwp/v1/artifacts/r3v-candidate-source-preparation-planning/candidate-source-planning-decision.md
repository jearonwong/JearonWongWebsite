# Candidate Source Planning Decision

## Recommended Next Wave

`R3W-CANDIDATE-SOURCE-PREPARATION-PLANNING-QA`

## Why

R3V creates the required candidate source preparation planning architecture without creating the candidate source. The package defines future candidate source role, path/naming placeholders, frontmatter/status language, preservation scans, non-claim controls, source/citation handling, table/layout readiness, creation stop gates, future command categories, and R3W QA instructions.

R3W QA is required before any candidate source planning repair, source strengthening, candidate source creation planning, or blocked decision.

## Specific Next Tasks

- QA whether R3V stayed preparation-planning-only.
- QA that no publication-candidate Markdown, artifact, HTML, PDF, DOCX, manifest, checksum, public route, CTA, staging, or release package was created.
- QA the placeholder path and naming rules.
- QA future frontmatter/status fields and non-claim language.
- QA preservation scans for structure, source refs, table IDs, Appendix A-H, and Appendix I deferral.
- QA source/citation and rejected-v0.2 exclusion planning.
- QA table/layout readiness and wide-table gate handling.
- Decide whether the next wave is candidate source planning repair, source strengthening, candidate source creation planning, or blocked.

## Out of Scope

- Publication-candidate Markdown creation.
- Artifact generation.
- HTML/PDF/DOCX creation.
- Manifest/checksum creation.
- Public route restoration.
- Public CTA restoration.
- Public staging.
- Public candidate, final, sealed, release-ready, or public release status.
